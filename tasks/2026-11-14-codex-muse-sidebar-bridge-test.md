# Codex 桥接测试：从电脑 Chrome 给 Muse 发一句话（2026-11-14）

## 背景

用户现在手机上，Muse 够不着她电脑上的前台 Chrome 扩展——前台浏览器只能连用户发消息的那台设备。
想搭一座桥：Codex 在电脑上操作 Chrome，打开 Muse 侧边栏（或 Muse 网页版），替用户发一句话给 Muse。
这样这句话就是从电脑发出来的，Muse 就能用前台浏览器干活了（比如 Facebook 首评、上传类任务）。

## 目标（只测桥，不发布任何东西）

让 Codex 从电脑 Chrome 发一句测试消息到主聊天，证明链路通。
成功标准：Muse 在主聊天里收到这句话。

## 步骤

1. **先检查 Chrome 调试端口 9222 是否开着**（之前查过是没开的）。
   - 如果没开：**不要自己关 Chrome、不要自己重启**。先停下来问用户，让用户重启 Chrome 时加上 `--remote-debugging-port=9222`（和 TikTok 传文件任务里用的方法一样），端口开了再继续。
   - 如果 playwright-core 还没装，先装上（沿用 TikTok 任务的环境准备）。
2. **连上 CDP 后，用 playwright-core 列出 targets，找到 Muse 扩展的侧边栏页面。**
   - 扩展 ID：`jnakhhjmpmoohbjgfccbccfoifnmbdjd`（Muse from Meta）。
   - 如果侧边栏面板直接驱动不了，**备选**：在 Chrome 里新开一个标签页打开 Muse 网页版（muse.ai），登录状态应该还在，用网页版聊天发消息。效果一样。
3. **在主聊天（Main chat，和八角一直在用的那个）里发且只发这一句：**
   > 桥接测试：我是 Codex，从你电脑的 Chrome 发来的。如果你收到这句，说明桥通了。
   - 如果分不清哪个是主聊天，不要猜，停下来写清楚。
4. **不要发别的**：不要替用户下任何发布指令，不要碰 Facebook / TikTok / YouTube / Pinterest，不要改任何设置，不要关 Chrome。
5. **在 status.md 里写结果并 push 回仓库**：怎么发出去的（侧边栏还是网页版）、9222 端口状态、遇到的问题。

## 限制

- 最多重试 2 次。侧边栏和网页版都驱动不了，就如实写清楚卡在哪一步，不要猜、不要硬编。
- 额度省着用，这就是个一句话的测试。
- 这是测试任务，不是发布任务。以后真的要发布，Muse 会另外发任务。
